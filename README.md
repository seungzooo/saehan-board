# 새한프라텍 출고·재고보드

영업 담당자가 외부에서도 품목별 출고 가능 수량과 재고 기준 시각을 확인하는 모바일 웹 대시보드.

**배포 주소:** https://saehan-board.vercel.app

영업 담당자는 사무실 밖에서 출고 가능한 수량을 확인해야 하지만, ERP 재고가 언제 집계되었는지 알 수 없으면 숫자를 신뢰하기 어렵습니다. 이 서비스는 담당자가 ERP 추출 엑셀을 업로드하면 최근 재고 스냅샷과 이후 변동을 바탕으로 가용재고를 계산하고, **집계 기준 시각과 시스템 반영 시각을 구분**해 표시합니다. ERP에 직접 연결하지 않습니다.

## 기술 스택

- **Next.js 16 (App Router) + React + TypeScript + Tailwind CSS** — 웹 UI
- **Prisma 7** — 데이터 접근 및 마이그레이션
- **Supabase PostgreSQL** — 데이터베이스
- **Vercel** — 웹 배포

## 시작하기

```bash
npm install
# 프로젝트 루트 .env에 아래 세 변수 설정 (실제 값은 저장소에 커밋하지 않음)
# DATABASE_URL=
# DIRECT_URL=
# UPLOAD_PIN=
npx prisma migrate deploy
npm run dev
```

`DATABASE_URL`은 앱 런타임 연결, `DIRECT_URL`은 Prisma CLI 연결에 사용합니다. `UPLOAD_PIN`은 업로드 보호 요구사항에 필요한 변수이나, **현재 소스의 PIN 검증 구현은 확인되지 않았습니다.** 환경변수만 추가해도 접근이 보호되지는 않습니다. 운영 시에는 Vercel에도 필요한 환경변수를 별도 설정해야 합니다.

## 재고 동작 규칙

```text
가용재고(박스) = 최근 재고 파일의 기초재고
               - 불량 차감(가장 최근 '불량 반영됨' 배치의 반영 시각 이후)
               - 출고 차감(최근 재고 반영 이후)
               - 수주 차감(최근 재고 반영 이후; F7 예정)
               - 기타 차감(최근 재고 반영 이후)
```

- **집계 기준 `stockAsOf`**: ERP에서 파일의 재고를 조회한 시각(담당자 입력). **반영 `uploadedAt`**: 앱에 업로드·저장한 시각. 둘은 서로 다르며, 차감 기준은 코드상 `uploadedAt`입니다.
- **사후 불량 반영 선택**: 재고 업로드에서 '예'를 선택하면 이전 불량 차감을 리셋하고, '아니오'를 선택하면 이전 불량 차감을 유지합니다. 출고·수주·기타는 최근 재고 반영 이후 기록만 차감합니다. `DEFECT_RESET_ON_UPLOAD` 환경변수는 사용하지 않습니다.
- **확인 필요 vs 0박스**: 최신 재고 파일에 품번이 없으면 수량을 계산하지 않고 **확인 필요**로 표시합니다. 파일에 0으로 명시되면 **0박스**입니다. 단, 정상 스냅샷이 있는 품목의 차감 결과는 음수가 될 수 있으므로 이를 누락 품목과 혼동하지 않습니다.
- **갱신 지연**: 최근 재고 파일의 `uploadedAt`에서 24시간이 지나면 표시합니다. `stockAsOf`가 없으면 '집계 시각 미확인'으로 표시합니다.
- **동일 품번 중복 행**: 요구사항은 같은 재고 파일에 동일 품번이 두 줄 이상이면 **합산 금지·확인 필요**입니다. **현재 `lib/excel/import.ts`는 합산 중이므로 아직 요구사항과 불일치합니다.**
- **PIN 보호 화면**: 업로드 화면과 저장 동작을 `UPLOAD_PIN`으로 보호하는 것이 요구사항이지만, **현재 확인한 코드에서는 미구현**입니다. F8 로그인 기능과 별개입니다.
- 취소된 변동은 가용재고 차감에서 제외합니다.

## 데이터 및 보안

`docs/data/`는 `.gitignore`에 포함됩니다. ERP 원본·정리본 등 **실데이터 파일은 Git 저장소에 포함하지 않습니다.** `.env*`도 Git에서 제외합니다. 코드에 비밀값이나 실데이터를 넣지 마세요.
