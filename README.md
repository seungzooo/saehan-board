# 새한프라텍 출고·재고보드

영업 담당자가 외부에서도 품목별 출고 가능 수량과 재고 기준 시각을 확인하는 모바일 웹 대시보드.

**배포 주소:** https://saehan-board.vercel.app

영업 담당자는 사무실 밖에서 출고 가능한 수량을 확인해야 하지만, ERP 재고가 언제 집계되었는지 알 수 없으면 숫자를 신뢰하기 어렵습니다. 이 서비스는 담당자가 ERP 추출 엑셀을 업로드하면 최근 재고 스냅샷과 이후 변동을 바탕으로 현재 재고를 계산하고, **집계 기준 시각과 시스템 반영 시각을 구분**해 표시합니다. ERP에 직접 연결하지 않습니다.

## 기술 스택

- **Next.js 16 (App Router) + React + TypeScript + Tailwind CSS** — 웹 UI (글꼴 Pretendard)
- **Recharts** — 분석·출고 차트
- **Prisma 7** — 데이터 접근 및 마이그레이션
- **Supabase PostgreSQL** — 데이터베이스
- **Vercel** — 웹 배포

## 시작하기

```bash
npm install
# 프로젝트 루트 .env에 아래 변수 설정 (실제 값은 저장소에 커밋하지 않음)
# DATABASE_URL=
# DIRECT_URL=
# UPLOAD_PIN=
# VIEW_CODE=
npx prisma migrate deploy
npm run dev
```

`DATABASE_URL`은 앱 런타임 연결, `DIRECT_URL`은 Prisma CLI 연결에 사용합니다. `VIEW_CODE`는 **사내 열람 코드**입니다. 홈·재고·분석을 포함한 모든 화면과 데이터 요청(`proxy.ts`)이 이 코드(또는 관리 코드)로 들어온 기기만 열립니다. 처음 열면 "새한프라텍 사내용 · 열람 코드를 입력하세요"가 나오고, 한 번 입력하면 그 기기에서 30일 유지됩니다(서명된 httpOnly 쿠키, 코드를 바꾸면 전부 무효). 비워 두면 아무도 들어올 수 없습니다. 열람 코드만으로는 업로드·변동 입력을 할 수 없습니다. `UPLOAD_PIN`은 업로드·변동 입력·업로드 취소 화면의 **관리 코드**입니다 — 열람 코드 화면에 관리 코드를 넣어도 조회할 수 있습니다. 비워 두면 그 화면들은 "관리자 PIN 미설정"으로 잠기고 열리지 않습니다. 운영(Vercel production·preview)에는 설정되어 있으며, 값은 재고 담당자에게 따로 전달합니다.

## 재고 동작 규칙

```text
현재 재고(박스) = 최근 재고 파일의 기초재고
                - 불량 차감(가장 최근 '불량 반영됨' 배치의 기준 시각 이후)
                - 출고 차감(기준 시각 이후)
                - 수주 차감(기준 시각 이후; 출고로 이행·연결된 수주는 제외)
                - 기타 차감(기준 시각 이후)
기준 시각 = 파일의 집계 기준 시각(stockAsOf), 모르면 반영 시각(uploadedAt)
```

- **집계 기준 `stockAsOf`**: ERP에서 파일의 재고를 조회한 시각(담당자 입력). **반영 `uploadedAt`**: 앱에 업로드·저장한 시각. 둘은 서로 다르며, 차감 기준은 `stockAsOf`(없으면 `uploadedAt`)입니다. 전날 입력한 출고는 다음날 파일이 이미 반영했으므로 차감에서 빠지고, 집계 시각 이후 출고는 남습니다.
- **사후 불량 반영 선택**: 재고 업로드에서 '예'를 선택하면 이전 불량 차감을 리셋하고, '아니오'를 선택하면 이전 불량 차감을 유지합니다. 출고·수주·기타는 최근 재고 반영 이후 기록만 차감합니다. `DEFECT_RESET_ON_UPLOAD` 환경변수는 사용하지 않습니다.
- **확인 필요 vs 0박스**: 최신 재고 파일에 품번이 없으면 수량을 계산하지 않고 **확인 필요**로 표시합니다. 파일에 0으로 명시되면 **0박스**입니다. 단, 정상 스냅샷이 있는 품목의 차감 결과는 음수가 될 수 있으며 화면에는 빨강 '재고 없음'으로 표시됩니다.
- **갱신 지연**: 최근 재고 파일의 `uploadedAt`에서 24시간이 지나면 표시합니다. `stockAsOf`가 없으면 '집계 시각 미확인'으로 표시합니다.
- **동일 품번 중복 행**: 같은 재고 파일에 동일 품번이 두 줄 이상이면 **합산하지 않고** 그 품번의 행을 모두 제외합니다. 그 품번은 **확인 필요**가 됩니다. 업로드 미리보기에 "중복 품번 N개"로 표시되고, 저장 전에 행 오류 확인을 거칩니다.
- **관리 코드 보호**: `/upload`, `/upload/[id]`, `/adjust`와 그 서버 액션은 관리 코드(환경변수 `UPLOAD_PIN`)를 입력해야 쓸 수 있습니다. 화면에는 "관리자 확인 — 재고 업로드와 변동 입력은 생산지원팀만 할 수 있습니다. 관리 코드를 입력하세요."만 보이고 PIN·환경변수 같은 내부 용어는 나오지 않습니다. 한 번 입력하면 이 기기에서 12시간 유지됩니다(서명된 httpOnly 쿠키, PIN을 바꾸면 전부 무효). 재고 검색·품목 상세·분석·변동 상세 조회는 PIN 없이 볼 수 있습니다. F8 로그인 기능과는 별개입니다.
- 취소된 변동은 차감에서 제외합니다. 정정은 원기록을 두고 차이값 기록을 추가합니다.
- **관리 대상 / 휴면**: 기준월(가장 최근 정상·내수 출고일이 속한 달) 포함 최근 12개 달(`config/stock.ts ACTIVE_MONTHS`)에 정상·내수 출고가 있는 품번이 관리 대상, 나머지 등록 품번은 휴면입니다. 2026-11-03 실데이터 기준 **2025-01 ~ 2025-12, 관리 대상 659 / 휴면 945** (등록 1,604). 홈·목록·곧 소진 집계는 관리 대상만 셉니다. 휴면 여부와 재고 수량은 서로 독립입니다.
- **목록 정렬**: 미확인은 최근 3개 달 정상·내수 출고 건수(전표 수) 많은 순 → 최근 출고일 → 품번 (출고량은 "최근 3개월 출고 N회 · ○○박스"로 표시만), 확인·곧 소진은 소진일수 짧은 순(산정 불가는 마지막). 정렬은 전체에 적용한 뒤 50개씩 나눕니다.
- **출고량 단위**: 출고 박스 환산은 `출고수량 ÷ 포장단위수량`이라 실제 단위는 품목의 포장단위입니다. 목록에는 포장단위수량이 1이면 "개"(낱개), 박스·파렛트·필름은 그 이름, 그 밖은 "포장"으로 표시합니다.
- **입수 표시**: 포장단위가 박스·파렛트·필름이면 "1박스당 105개"(1파렛트당·1필름당), 규격 코드(83*155 등)면 "1포장(83*155)당 90개", "없음"·빈 값이면 "입수 105개".
- **단종**: 품명이 "폐기"로 시작하는 품목은 목록 맨 아래에 회색과 "단종" 배지로 표시합니다.
- **분석 기준**: 분석 탭은 정상 출고(판매형태 전체)를 판매량으로 쓰고 반품은 따로 보여 줍니다. 재고 화면의 정상·내수 필터는 분석에 적용하지 않습니다. 대상은 생산 실적과 정상 출고가 모두 있는 **635개** 품번입니다(정상·내수로 좁히면 595개). 자료 범위 밖의 달은 '자료 없음'으로 계산에서 빼고, 범위 안의 빈 달은 실제 0입니다. 교수님 데모와의 산식 차이는 CLAUDE.md F5 절에 있습니다.
- **월별 출고량**: 수량은 판매실적 원본의 `출고수량`(낱개)을 그대로 합산합니다. 전체 요약은 생산 기록과 무관하게 전체 거래처의 정상 출고, 반품은 따로입니다. 품목을 고르면 포장단위가 박스이고 입수가 확인된 경우에만 박스로 바꿔 "2박스 50개"처럼 보여 주고, 그 밖은 낱개입니다.
- **집계 완료와 비교**: 마지막 출고일만으로 그 달이 끝났다고 보지 않습니다. 자료가 이어지는 앞선 달은 완료, 마지막 달은 가장 최근 출고실적 업로드에 저장된 **집계 완료 월**로 확인합니다. 연도를 고르면 그 해 완료 구간과 전년 같은 구간을, 전체 기간은 최근 12개월과 직전 12개월을 비교합니다. 직전 합이 0이면 증감률 산정 불가, 누락·미완료 달이 있으면 비교 자료 부족으로 표시합니다.
- **새 출고·생산실적을 올릴 때**: 업로드 화면에서 파일을 고르면 "이 파일의 집계 완료 월"이 자동으로 채워집니다. 파일의 마지막 날짜가 그 달 말일(또는 마지막 영업일)까지면 그 달, 아니면 전달입니다 — 예: 3월 15일까지 있는 파일은 2월. 그 달 자료가 실제로 다 들어온 파일이면 값을 바꿔서 저장하세요. 저장한 뒤에도 업로드 이력에서 그 업로드를 눌러 상세 화면에서 고칠 수 있습니다(PIN 필요). 분석 화면 위에 지금 쓰는 값과 그 값을 정한 업로드가 보입니다.
- **재고 일부 갱신**: 재고 업로드에서 "일부 갱신"을 고르면 이번 파일에 있는 품목만 새 수량·새 집계 시각이 되고, 파일에 없는 품목은 이전 수량과 **이전 집계 시각**을 그대로 유지합니다(그 시각 이후 입력한 출고·불량도 계속 차감). 품목마다 집계 시각이 달라질 수 있어 상세·목록·검색 카드에 품목별 집계 시각을 표시합니다. 사후 불량 리셋도 그 파일에 실제로 들어 있던 품목에만 적용됩니다.
- **같은 재고 파일 다시 반영**: 같은 파일이라도 "사후 불량 반영" 선택이나 집계 시각을 바꾸면 새 기준으로 저장됩니다(예: 09:00 파일을 올린 뒤 생산지원팀이 불량 반영을 확인해 같은 파일을 "예"로 다시 반영). 같은 설정으로 다시 누르면 중복으로 보고 저장하지 않습니다.
- **거래처 유형**: B2B/B2C 값은 임시 분류라 분석 화면에서 숨겼습니다. `?seg=` 주소도 전체 거래처로 집계합니다. 데이터는 보존합니다.
- **속도**: Vercel 함수는 DB와 같은 뭄바이(`bom1`)에서 돕니다. 실적에서 나오는 집계는 캐시하고 실적 업로드·취소·집계 완료 월 수정 때만 새로 계산합니다(재고 수량은 늘 실시간). 분석 연도 버튼은 서버를 거치지 않고 바로 바뀝니다.
- **예상 소진일수** = 현재 재고 ÷ 최근 30일 일평균 출고(출고실적 정상·내수, 정상·내수 출고 마지막 날짜 기준). 3일 이하면 '곧 소진'. 출고 이력이 없으면 '산정 불가'.

## 운영 안내 (재고 파일)

업로드 화면의 "운영 안내"와 같은 내용입니다. 시각·담당은 **회사 확정 전 운영 가정**입니다.

- **누가·언제**: 생산지원팀 재고 담당자가 매일 오전(업무 시작 후 10시까지 권장) ERP(몰드)에서 재고 엑셀을 내려받아 `/upload`(관리 코드 필요)에 올립니다. 그 뒤 불량·출고 등 변동은 앱 "변동 입력"에 **한 번만** 기록하면 영업 화면에 바로 반영됩니다(별도 시트 입력 없음).
- **입력**: "집계 기준 시각"(ERP에서 재고를 조회한 시각)과 "사후 불량이 파일에 반영됐는지"를 직접 고릅니다. 앱은 파일만으로 반영 범위를 추정하지 않습니다. 집계 시각 이전에 입력한 출고·수주·기타는 파일이 반영한 것으로 보고 해제, 이후 입력분은 계속 차감합니다. 불량은 "예"를 고른 파일에 들어 있던 품목만, 그 파일 집계 시각 이전 것을 해제합니다. 미리보기가 직전 기준 이후 입력된 불량과 "직전 기준 − 불량 = 이 파일" 일치 여부를 보여 줍니다.
- **올리지 않으면**: 품목의 집계 기준 시각에서 **24시간**(`config/stock.ts STALE_AFTER_HOURS`)이 지나면 영업 화면에 "오늘 자료 미반영"이 표시됩니다. 마지막 확인 수량과 시각은 보이지만 요청 수량 판정(충족·부족)은 "판정 보류"가 됩니다.
- **잘못 올렸을 때**: 업로드 화면의 "이전 기준재고로 복구"(또는 업로드 상세의 취소)로 직전 파일을 다시 기준으로 삼습니다. 현재 기준보다 이전 집계 시각의 파일은 앱이 받지 않고, 같은 파일·같은 설정은 다시 저장되지 않습니다.
- **영업 화면 문구**: 결과는 "확인 재고 기준"입니다. 출고 예약·배송 일정을 잡은 것이 아니므로 "확보 완료"·"납기 확정"으로 쓰지 않습니다.

## 데이터 및 보안

`docs/data/`는 `.gitignore`에 포함됩니다. ERP 원본·정리본 등 **실데이터 파일은 Git 저장소에 포함하지 않습니다.** `.env*`도 Git에서 제외합니다. 코드에 비밀값이나 실데이터를 넣지 마세요.

## 주요 명령어

| 명령어 | 설명 |
| --- | --- |
| `npm run dev` | 로컬 개발 서버 |
| `npm run build` | 프로덕션 빌드 |
| `npm run test` | Vitest 테스트 |
| `npm run test:e2e` | Playwright E2E 테스트 (읽기 전용 — 운영 DB에 쓰지 않음) |
| `DATABASE_SCHEMA=demo npx tsx scripts/demo-schema.ts` | 시연·쓰기 e2e용 분리 스키마 `demo` 초기화 (public은 건드리지 않음). 서버를 `DATABASE_SCHEMA=demo`로 띄우고 `E2E_DEMO=1 npx playwright test e2e/demo-scenario.spec.ts` |
| `npm run db:migrate` | 개발용 Prisma 마이그레이션 |
| `npm run db:seed` | 로컬 정리본 기반 시드 (해당 파일 필요) |
| `npx tsx scripts/rebuild-monthly.ts` | 월별 집계(MonthlyStat) 전체 재계산 |

설계 의도, 데이터 모델, 기능별 상세 스펙과 현재 구현의 차이는 [CLAUDE.md](./CLAUDE.md)를 참고하세요.
